# 空间数据与模型

## 从平面图到可拾取的书架

1. 为建筑、楼层和书架分配稳定业务 ID。模型清单按版本记录楼层、模型 URL、标定信息和书架映射。展示名、网格序号和 Three.js 运行时 UUID 都可能变化。
2. 在 Blender 中按楼层组织墙体、入口、书架和楼梯或电梯连接点。在书架父节点写入业务 ID，导出到 glTF 节点的 `extras`。合并网格时保留可区分的拾取边界。运行时由 GLTFLoader 载入后建立双向查找。
3. 建议约定三维世界以米为单位、Y 轴向上。每层清单记录平面图原点、比例、旋转、轴向和楼面标高，SpatialManager 将二维点映到该层三维位置。楼层图像像素只在绘制边界使用。服务端路线点所用单位、轴向和版本需双方确认。[Go 服务适配](../../three-party/library-go.md)
4. 发布前以入口、已知书架和换层点核对二维与三维位置。用至少三个不共线的已知点检查方向、比例和往返误差，按实际平面图精度登记允许误差。压缩前后核对每个书架的可拾取节点、唯一业务 ID 和所属楼层。

## 版本和异常

GLB、二维底图和映射清单作为同一模型版本发布。缓存键含版本；同时加载相同版本的模型和映射后再启用按 ID 定位。发现重复书架、未知楼层或服务端返回其他模型版本时，保留位置文字、提示无法在当前图上定位，并按需重新获取清单。绘制路线时逐段校验楼层和坐标，跨层只在声明的连接点衔接。
