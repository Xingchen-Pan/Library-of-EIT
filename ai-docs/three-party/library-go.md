# library-go 服务适配

Web 仓库维护 Fetch 客户端、响应校验、字段转换和界面反馈。馆藏中转、实体位置解析、图数据与 A* / Dijkstra 路径规划由独立的 library-go 仓库维护。2026-11-23 对照服务端提交 `d56312d`，HTTP 路由注册了 `GET /healthz`，返回 `{"status":"ok"}`。健康检查只表明进程可响应。下表列出三维导览需要双方商定的能力。[服务端路由快照](https://github.com/EIT-Library/library-go/blob/d56312da62d4fa1c7fb31c36f4b6ca3a344f289d/internal/api/router.go) · [服务端 API 约定](https://github.com/EIT-Library/library-go/blob/d56312da62d4fa1c7fb31c36f4b6ca3a344f289d/ai-docs/architecture/api.md)

| 候选能力 | Web 发出的信息 | 需要返回的信息 | 界面行为 |
| --- | --- | --- | --- |
| 检索馆藏 | 查询词、分页条件 | 书目 ID、标题、可选择的馆藏副本及其 ID | 同一书目可有多个位置，由读者选具体副本。 |
| 查询副本位置 | 副本 ID | 位置文字、可定位状态；具备映射时附楼层 ID、书架 ID 和模型版本 | 展示位置文字，通过 ViewerController 定位书架。 |
| 取得模型元数据 | 建筑 ID、所需版本 | 模型版本、楼层、GLB 与平面图清单地址 | 用模型版本关联缓存和空间映射。 |
| 规划室内路线 | 手动或二维码起点 ID、目标书架 ID、模型版本 | 按行走顺序排列的楼层分段、各段坐标点、换层连接点和目标 | 二维与三维共用分段；无可达路线时保留书架位置。 |

## 字段转换示例

以下仅为协商时使用的定位样例。沿用 Go 文档中的 JSON `snake_case` 约定，在 Web 的 API 边界一次转换成业务层的 `floorId`、`shelfId` 和 `modelVersion`。

```json
{"copy_id":"copy-42","floor_id":"2F","shelf_id":"2F-A03","model_version":"sample-v1"}
```

若用户从列表选中 `copy-42`，Web 先校验必需字段和版本，再在该层清单查找 `2F-A03`。书架缺失时显示位置文字并提示当前模型缺少映射。网络失败允许重试，查询无结果显示空列表，无路线显示不可达；取消的旧请求不触发错误提示或相机定位。

## 联调交接

双方在服务端契约中确认路由、访问权限、字段可空性、分页和错误码，并约定路线坐标系、距离单位及模型版本不匹配时的恢复方式。先用明确标为样例的数据覆盖同层、跨层、未知书架和无路线，再以双方认可的测试服务和真实响应重跑相同场景，将服务版本与结果记入 Web 任务。
